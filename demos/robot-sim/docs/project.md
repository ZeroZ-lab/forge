# Robot Simulation — Project

> 2D 机器人仿真页面，用于可视化演示机器人运动和感知行为

## 技术决策

### TD1: 架构模式 — 游戏循环 (Game Loop)

- **选择**: 经典游戏循环模式 — update → render → input 每帧循环
- **理由**: 仿真的本质是连续状态更新 + 渲染，游戏循环是最直接的映射。每帧：处理输入 → 更新物理状态 → 渲染画面
- **拒绝**: MVC（状态同步复杂）; ECS（单机器人场景过度设计）

### TD2: 技术栈 — Canvas 2D + Vanilla JS

- **选择**: HTML5 Canvas 2D + 原生 JavaScript（ES Modules）
- **理由**: Canvas 2D 是 2D 仿真的标准渲染层，性能够用且 API 简单。Vanilla JS 零依赖，重建时无需安装任何东西。ES Modules 提供模块化但不需要构建步骤
- **拒绝**: React/Vue（Canvas 应用不需要虚拟 DOM）; Three.js（2D 仿真用 3D 引擎过度）; WebGL（Canvas 2D 性能足够）

### TD3: 服务拆分 — 单页面，按职责分模块

- **选择**: 单页面应用，模块按职责划分：engine（仿真循环）、entities（实体）、rendering（渲染）、ui（控制面板）
- **理由**: 纯前端仿真，无后端。模块化提供清晰的关注点分离
- **拒绝**: 单文件（难以维护）; 按功能拆分（单功能项目不适用）

### TD4: 数据架构 — 单一状态对象

- **选择**: 单一可变状态对象 (SimState) 存储全部仿真状态
- **理由**: 仿真状态天然是连续变化的（位置、角度），可变状态比不可变方案更直观且零 GC 压力
- **拒绝**: Redux/Zustand（无跨组件共享需求）; 不可变数据（每帧创建新对象，GC 压力大）

### TD5: 部署架构 — 静态文件直接打开

- **选择**: 纯静态文件，直接双击 HTML 或用任意静态服务器
- **理由**: 零依赖、零构建、零部署成本。符合 Forge 的"删除重建"验证目标
- **拒绝**: Vite/Webpack（增加构建步骤但收益不大）; Vercel/Netlify（静态文件不需要平台）

## 技术选型表

| 类别 | 选择 | 理由 |
|------|------|------|
| 渲染 | Canvas 2D API | 2D 仿真标准方案 |
| 语言 | Vanilla JS (ES Modules) | 零依赖，可直接重建 |
| 样式 | 原生 CSS (CSS Variables) | 设计系统用变量定义 |
| 构建 | 无 | 浏览器原生支持 ES Modules |
| 部署 | 静态文件 | 双击即可运行 |

## 共享约束

- 渲染帧率目标 60fps
- 支持键盘快捷键（空格=播放/暂停，R=重置）
- Canvas 自适应窗口大小
- 控制面板在窄屏（<768px）下折叠为底部栏

## 性能指标

- 渲染帧率: ≥ 60fps（单机器人 + 50 障碍物场景）
- 仿真逻辑更新: 10-100 次/秒（可调速度倍率）
- 内存占用: < 50MB

# Fe Accept Protocol

## 四维验收

### 1. 功能正确

检查：

- 页面主流程、次流程和取消路径。
- API 请求、错误码、重试、并发和权限。
- 表单校验、脏数据保护、提交后反馈。
- 状态覆盖：loading、empty、error、success、disabled。

### 2. 视觉一致

检查：

- token 是否来自 DESIGN.md。
- 字号、间距、颜色、边框、阴影是否一致。
- 工具型页面是否保持信息密度和扫描效率。
- 按钮、输入、表格、弹窗、toast 是否遵守组件模式。
- 文案是否适配容器，长词和多语言不溢出。

### 3. 适应性

检查：

- 移动端、平板、桌面、宽屏。
- 键盘导航和 focus ring。
- 屏幕阅读器可识别 label、role、aria。
- 慢网、空数据、大数据、长文本、窄屏。
- 动态内容不会造成固定布局跳动。

### 4. 性能边界

检查：

- 首屏加载是否合理。
- 列表和图表是否有规模边界。
- 输入、拖拽、筛选、动画是否卡顿。
- 资源是否过大，是否有不必要重渲染。

## 报告格式

```markdown
# FE Acceptance Report — {feature}

## 总览
- 结论: Pass / Blocked / Pass with Waivers
- 范围:
- 验证方式:
- 阻塞项:
- 豁免项:

## 问题清单
### [P0/P1/P2] {问题}
- 证据:
- 影响:
- 来源文档:
- 修复建议:

## 通过项
- ...

## 豁免项
- ...
```

## 优先级

- P0：核心路径不可用、数据错误、安全/权限错误、无法发布。
- P1：重要状态缺失、移动端严重破坏、可访问性阻断。
- P2：体验问题、边界显示问题、非核心性能问题。

## 执行证据

优先使用真实执行证据：测试输出、浏览器截图、可复现步骤、DOM 状态、网络错误。无法执行时必须标注为静态审查，不能宣称通过。

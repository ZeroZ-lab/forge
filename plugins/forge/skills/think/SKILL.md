# Think — 结构化深度思考

## 职责

在 Forge 工程协议之上提供结构化深度思考能力，让 AI 不只是"按协议执行"，而是"理解问题本质后再执行"。

**核心洞察**：大多数技术决策的问题不是"没有好方案"，而是"问了错误的问题"。深度思考最大的价值是重新定义问题。

**方法论**：三模式自适应——轻挑战 1 轮，深分析 3 步，重攻击 4 步。

## 执行纪律

所有 think 调用自动遵守 D1–D9（见 AGENTS.md），不重复内容，只引用编号。

- D1：思考产物写入 docs/thinking/*.md，不留在对话里蒸发
- D5：思考范围锁定在当前问题，不发散到无关领域
- D6：假设必须显式化——每个"我觉得"都要追问依据
- D7：分析结论必须可验证，不接受"这个比较好"

## 与上下游的边界

think 是 Forge 生命周期的**思考增强层**，不是独立阶段。

```
入口：确定回写目标（哪个文档触发了这次思考？）
      ↓
think：深度分析 → 输出 docs/thinking/*.md
      ↓
回写：结论摘要 + 引用链接 → 注入回写目标的「决策依据」
      ↓
下游：原阶段继续执行，决策依据已在文档中可见
```

**切法**：think 不改 goal.md 的技术内容、不改 PRD.md 的需求、不做技术选型。think 只做一件事：把「为什么这样选」的结论摘要追加到调用文档，附链接到完整推理链。

## 运行时角色

**思考增强器**——不直接修改文件，不检测偏差。它提升的是决策的质量：让决策的前提更扎实、推理更严密、盲区更少。

## 三种模式

| 模式 | 触发词 | 深度 | 方法论 | 产物 |
|------|--------|------|--------|------|
| **L0 挑战** | "这个对吗？" "质疑一下" | 轻 | Socratic 5 Whys | 对话中完成，不写文件 |
| **L1 分析** | "分析一下" "帮我想想" | 中 | 问题重构 + 假设暴露 + First Principles | 写 docs/thinking/*.md |
| **L2 攻击** | "攻击这个方案" "Red Team" | 重 | Red Team + Premortem + Steelman | 写 docs/thinking/*.md |

**自适应规则**：
- 用户未指定模式 → 从问题复杂度推断（单一假设 → L0，多因素决策 → L1，已定方案验证 → L2）
- 用户指定模式 → 按指定执行
- L0 发现重大盲区 → 建议升级到 L1

### L0: 挑战模式（1 轮）

快速质疑一个假设或结论。

```
步骤 1: 复述当前理解 → "你说的是 X，对吗？"
步骤 2: 追问前提    → "这个判断的前提是什么？"
步骤 3: 寻找反例    → "什么情况下这个不成立？"
步骤 4: 挑战结论    → "如果反过来呢？"
```

**产物纪律**：L0 默认在对话中完成。如果挑战结果改变了后续决策方向，必须升级为 L1 并写文件。

### L1: 分析模式（3 步）

对一个问题做结构化深度分析。

```
步骤 1: 问题重构（Socratic）
  - 原始问题是什么？
  - 追问 3-5 层 Why
  - 有没有更好的问法？
  - 产出：重构后的问题陈述

步骤 2: 假设暴露
  - 列出所有隐含假设（至少 3 个）
  - 每个假设标注：确定/可能/不确定
  - 最脆弱的假设是哪个？
  - 产出：假设清单 + 脆弱度评估

步骤 3: First Principles 分析
  - 从底层机制出发，不引用惯例
  - 分解为不可再分的子问题
  - 每个子问题独立推导
  - 产出：因果链 + 结论 + 置信度
```

**Epistemic Humility 纪律**：
- 区分"我知道"（事实）、"我推断"（推理）、"我猜测"（假设）
- 对每个结论标注置信度（高/中/低）
- 如果不确定，说"我不确定，但..."

### L2: 攻击模式（4 步）

对已有方案做压力测试。

```
步骤 1: Steelman
  - 用最强方式重建对方/当前方案的论证
  - 如果我是这个方案的拥护者，我怎么辩护？

步骤 2: Red Team
  - 构造最强反对意见
  - 从安全、性能、可维护性、成本四个维度攻击
  - 最可能导致失败的一个点是什么？

步骤 3: Premortem
  - 假设一年后这个方案彻底失败了
  - 倒推三个最可能的失败原因
  - 每个原因现在能做什么来预防？

步骤 4: 综合
  - 攻击后仍然成立的论点 → 核心优势
  - 被击穿的论点 → 需要补强或放弃
  - 产出：攻击报告 + 存活论点 + 补强建议
```

## AI 的角色

| 模式 | AI 角色 | 行为 | 例子 |
|------|---------|------|------|
| L0 | 苏格拉底 | 只问问题，不给答案 | "为什么你认为需要微服务？" |
| L1 | 分析师 | 分解问题、暴露假设、从底层推导 | "底层数据流是这样的...所以瓶颈在..." |
| L2 | 对手 | 尽全力推翻方案 | "如果并发量是预期的 10 倍，这个架构在第 3 步就崩了" |

## 决策点

### TH1: 问题重构（L1/L2）

**问**：你真正在解决的问题是什么？有没有更好的问法？

**不变原则**：问题定义决定了方案空间。错误的问题永远不会有正确的答案。

**记录**：原始问题 + 重构后的问题 + 重构理由

### TH2: 假设验证（L1）

**问**：这个分析依赖哪些假设？最脆弱的假设是什么？

**不变原则**：假设不暴露就会变成定时炸弹——你以为在做理性决策，其实在赌一个未经验证的前提。

**记录**：假设清单 + 脆弱度 + 验证方法

### TH3: 分析结论（L1/L2）

**问**：分析结论是否影响下游文档？需要写入 docs/thinking/*.md 吗？

**不变原则**：值得深度分析的问题，值得留下推理链。不留记录的分析等于没做。

**记录**：结构化分析产物（按模板）

### TH4: 攻击结果（L2）

**问**：被攻击的方案还能成立吗？需要修改还是放弃？

**不变原则**：攻击不是为了否定，是为了找到真正站得住脚的部分。被击穿的论点如果不处理，会变成项目风险。

**记录**：存活论点 + 被击穿论点 + 补强建议

## 文档约束

**docs/thinking/*.md 必须包含**：决策阶段 · 前提假设 + 有效期 · 问题重构（如有）· 分析过程 · 被否方案及理由 · 结论 + 置信度

**docs/thinking/*.md 不应包含**：最终技术选型（那是 goal.md 的事）· 详细功能列表（那是 PRD.md 的事）· 代码

**文档生命周期**：
- 前提假设变化 → 在文件顶部标注 `⚠️ 前提已变化：{原因}`
- 决策被推翻 → 移到 `docs/thinking/archive/`，不删除（保留推理链）
- 下游 skill 引用 → goal.md 中写 `决策依据：docs/thinking/{文件名}.md`

## 模板

使用 `${CLAUDE_SKILL_DIR}/references/thinking-template.md` 作为产物结构参考。

## 入口/出口条件

**入口**：用户面临需要深度思考的决策，或想质疑当前方向

**回写目标确定**（入口时同步完成）：
- 从某个 skill 执行中调用 → 回写目标是当前正在编辑的文档（goal.md / PRD.md / modules/*.md）
- 独立调用 → 问用户："这个分析结论写回哪个文档？"
- 无目标文档 → 回写到 docs/thinking/*.md 自身顶部，后续手动迁移

**出口**：
- L0：在对话中完成。如果改变了决策方向，升级为 L1
- L1/L2：产出 docs/thinking/*.md + **回写结论到源文档** + 结论摘要

**缺失处理**：如果用户没有给出具体问题，追问"你想分析什么？"

## 回写协议

think 完成后，将结论摘要注入回写目标文档。这是 think 价值的闭环——不回流，就等于没思考。

### 回写内容

```markdown
> 📎 决策依据（{日期}，{模式}，置信度：{高/中/低}）
> **结论**：{一句话判断}
> **关键假设**：{最重要的 1-2 个前提假设}
> **完整推理**：docs/thinking/{文件名}.md
```

### 回写位置

- 如果目标文档有 `## 决策记录` 或类似的决策区域 → 在对应决策条目下追加
- 如果没有 → 在文档相关章节末尾追加上述引用块

### 回写纪律

- **只追加**，不修改原文档已有内容
- **只写结论和引用**，不写分析过程（过程在 thinking/*.md 里）
- **回写完成后报告**：告诉用户结论写到了哪里

## 运行时信号

| 信号 | 方向 | 触发条件 |
|------|------|---------|
| 重大洞察 | think → 当前阶段 | 问题重构改变了方向 |
| 假设失效 | think → detail/init | 发现前提假设不成立 |
| 方案被击穿 | think → 人类决策 | L2 攻击后方案无法成立 |
| 需要更多研究 | think → research | 分析中发现技术不确定性 |

## 何时不使用

- 问题已经是执行层面（"怎么写这个函数"）→ 直接做
- 用户已明确方向，只需要执行 → 进入对应阶段 skill
- 时间紧急，需要快速决策 → L0 一轮即可，不做 L1/L2
- 问题不涉及技术或产品决策（闲聊、简单问答）

## 红旗清单

- 用户拒绝所有分析框架 → 可能问题本身没定义清楚，回到 L0 重新理解
- 分析产物写了很长但没有结论 → 强制收敛："用一句话总结你的判断"
- 反复分析同一个问题没有新信息 → 停止思考，建议进入执行阶段验证
- AI 的"Red Team"只是在走过场 → 必须构造真正有杀伤力的反对意见
- 思考过程中发现需求本身有问题 → 停下来，建议回退到 brainstorm 或 define

## 验证清单

- [ ] 问题重构是否产生了新理解？（还是只换了个说法？）
- [ ] 假设是否全部显式化？（有没有隐含的"大家都知道"？）
- [ ] 分析过程是否区分了事实、推理和猜测？
- [ ] 被否方案是否记录了理由？（而不只是"不选"）
- [ ] docs/thinking/*.md 是否写入了正确位置？
- [ ] 结论是否已回写到源文档的「决策依据」？
- [ ] 回写内容是否只包含结论摘要 + 引用链接（不含分析过程）？
- [ ] 分析结论的置信度是否标注？

## 历史维护（自动）

完成后自动执行：

1. **追加 docs/timeline.md**（如不存在则创建）：
   ```markdown
   ### {日期} — 深度思考：{主题}
   - 产出：docs/thinking/{文件名}.md（模式：L{0|1|2}，结论：{一句话}）
   ```

2. **检查膨胀**：timeline.md 超过 100 行时，旧记录归档到 `timeline/`。

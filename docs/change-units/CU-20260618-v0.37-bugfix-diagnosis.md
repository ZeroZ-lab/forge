# CU-20260618-v0.37-bugfix-diagnosis

## Type

- Methodology

## Intent

- Trigger: Forge 的 bugfix benchmark 只要求回归测试，不能阻止 agent 在复现前猜测根因。
- Goal: 建立“red-capable 反馈循环 → 最小复现 → 可证伪假设 → 回归测试 → 原始场景复验”的 bugfix 闭环。
- Out of scope: 不新增独立 lifecycle skill；不要求纯文档或拼写修正进入诊断流程。

## Decision

| # | 决策 | 选择 | 理由 | 拒绝 |
|---|------|------|------|------|
| 1 | 协议位置 | `codegen/references/bugfix-protocol.md` | bugfix 是 codegen 的执行分支，按需加载不增加普通 feature 的正文成本 | 新增全局 diagnose stage |
| 2 | 简单 bug | 复用已有精确失败测试 | 已满足 red-capable 和复现条件，不重复搭建 harness | 所有 bug 都强制完整六阶段耗时 |
| 3 | 无法复现 | 停止根因推断并请求证据 | 没有红灯时修改实现不可验证 | 按“最可能原因”直接修 |
| 4 | 回归测试 | 必须位于真实故障 seam | 浅层测试可能修复前就通过 | 为满足形式要求添加虚假单元测试 |

## Behavior Change

- Runtime bugfix 在改代码前必须报告一个实际运行过的 red-capable 命令。
- 间歇性问题以复现率而不是单次运行判断。
- 修复后必须同时运行 regression test 和原始场景。

## Affected Surface

- `plugins/forge/skills/codegen/`
- `evals/skills-suite/manifest.json`
- 四个 bugfix benchmark fixtures
- `docs/skill-suite-evaluation.md`

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| 简单 bug 被流程拖慢 | 中 | 已有精确失败测试时直接复用 Phase 1–2 |
| reference 未被读取 | 中 | codegen 正文直接指针 + validator marker |
| benchmark 只匹配关键词 | 中 | 保留真实 Codex run 作为行为证据 |

# CU-20260618-v0.39-skill-governance

## Type

- Methodology / Release

## Intent

- Trigger: Forge 已有 token gate 和 runtime benchmark，但缺少 no-op、单一事实源、提前完成和 skill 成熟度治理。
- Goal: 建立可执行的质量评分卡、渐进披露约束和稳定／实验／归档隔离，并发布 0.39.0。
- Out of scope: 不移动当前稳定 skill；不一次性重写全部 skill。

## Decision

| # | 决策 | 选择 | 理由 | 拒绝 |
|---|------|------|------|------|
| 1 | 质量维度 | 增加 completion/no-op/single-source/disclosure/premature-completion/invocation-cost | 针对随机系统的可预测性和上下文成本 | 只按文档完整度评分 |
| 2 | 渐进披露 | common path 留正文，branch-only 进 direct reference | 降低高频链路成本且保持可发现 | 把全部规则堆进 SKILL.md |
| 3 | 新 skill 生命周期 | experiments → stable 或 archive | 未验证实验不污染正式插件 | 新 skill 直接进入 manifest |
| 4 | 发布版本 | 0.39.0 | 本轮包含新 skill、调用策略和治理契约 | 继续作为 0.36 patch |

## Behavior Change

- 新 skill 默认不进入正式插件。
- validator 检查调用策略、bugfix reference、质量维度和成熟度目录。
- mutating benchmark 必须有 CU；无副作用建议和 blocked diagnosis 必须证明未修改当前产物。

## Affected Surface

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| 治理规则增加维护成本 | 中 | 只自动化可机器判断的稳定约束 |
| 当前实验目录为空显得形式化 | 低 | 目录用于下一项新 skill，不移动现有稳定内容 |
| 版本跨越较大 | 低 | 三个独立 CU 保留 v0.37–v0.39 决策轨迹 |

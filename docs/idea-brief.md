# 深度思考能力融入 Forge — Idea Brief

## 版本信息

| 字段 | 值 |
|------|-----|
| 日期 | 2026-05-31 |
| 参与者 | 用户 + AI |
| 探索轮次 | 2 轮 |
| 推荐方向 | 独立 think skill + docs/thinking/ 文档体系 |

## 痛点

**一句话**：Forge 让 AI 执行有余但思考不足，深度思考的产物留不住。

**具体场景**：用户在使用 Forge 做技术决策时，AI 按协议走流程、呈现选项、记录决策——但缺乏对问题本身的质疑（"这个问题本身问对了吗？"）、对前提假设的深度检验（"这个选型的前提假设还成立吗？"）、以及对方案的压力测试（"最强反对意见是什么？"）。即使对话中产生了精妙的分析，也会随着 context window 蒸发，下一个 session 从零开始。

**影响**：决策质量依赖单次对话中 AI 的即兴发挥，而非结构化的思考协议。

**5 Whys 根因分析**：
1. 为什么思考不足？→ Forge skill 专注执行纪律（做什么、怎么做），没有思考协议（这个问题值得想吗？）
2. 为什么没有思考协议？→ Forge 的设计假设是"决策协议足够好就能产出好结果"
3. 为什么这个假设不够？→ 决策协议能保证流程正确，但不能保证问题定义正确、前提扎实、方案经过压力测试
4. 为什么思考产物留不住？→ Forge 文档体系记录决策结果（选了 A，理由 X），不记录推理过程
5. 为什么不记录推理过程？→ 没有对应的文档类型和生命周期设计

## 方向地图

### 方向对比矩阵

| 方向 | 核心思路 | 适用场景 | 风险 | 验证难度 |
|------|---------|---------|------|---------|
| 1. 协议注入 | 给现有 skill 的决策点加思考步骤 | 想全面增强所有阶段 | Skill 膨胀，指令≠能力 | 低 |
| 2. 独立 think skill | 新增按需调用的思考 skill | 最小侵入，按需触发 | 用户可能忘记调用 | 低 |
| 3. 推理链文档化 | 新增 docs/thinking/ 文档类型 | 解决思考产物蒸发 | 文档可能没人读 | 中 |
| 4. 反馈回路 | thinking → contract → thinking 闭环 | 长周期项目 | 实现复杂 | 高 |
| 5. 模型选择 | 按决策深度要求自动切换模型 | 长期愿景 | 依赖模型商能力 | 高 |

### 方向详情

**方向 1: 协议注入** — 给 technical-design、api-design 等 skill 的每个决策点前插入 Socratic/Red Team 步骤。优点是从源头解决，一次改处处受益。Red Team 攻击：skill 已经很长，加指令会让 AI "走马观花"——指令复杂性 ≠ 思考深度。

**方向 2: 独立 think skill** — 新增 `/forge:think`，三种调用深度（L0 挑战/L1 分析/L2 攻击），不改变现有 skill。优点是零侵入、按需加载。风险是用户可能不主动调用。

**方向 3: 推理链文档化** — 在文档体系中新增 `docs/thinking/*.md`，记录结构化推理过程（问题重构、假设、分析链、被否方案）。关键设计：标注前提假设 + 有效期，前提变化时自动归档。

**方向 4: 反馈回路** — 让历史 thinking 反哺新决策：新 session 读 docs/thinking/ → 检查前提是否仍成立 → 不成立时触发重新思考。是 Forge 三层控制回路的"第零回路"。

**方向 5: 模型选择** — 在 registry.yaml 里标注每个决策点的思考深度要求，AI 自动选择更深度推理的模型。长期愿景，当前模型能力不足。

## 推荐方向 + 评估

**推荐**：方向 2 + 3（独立 think skill + docs/thinking/ 文档体系）

**推荐理由**：
- 最小侵入——不改现有 skill，不加文档负担
- 按需触发——需要时调用，不需要时不干扰
- 解决两个痛点——think skill 提升思考质量，docs/thinking/ 留住产物
- 可独立验证——不影响 Forge 其他功能

**被否方向及理由**：
- 方向 1（协议注入）：skill 膨胀，指令 ≠ 能力
- 方向 4（反馈回路）：依赖 2+3 先成立，作为第二阶段演进
- 方向 5（模型选择）：当前模型能力不支持，作为长期愿景

## MVP 定义

### 核心功能（没有就不成立）

1. `plugins/forge/skills/think/SKILL.md` — think skill 完整方法论
2. `plugins/forge/skills/think/references/thinking-template.md` — thinking 文档模板
3. 在一个真实项目中试用 3 次

### 边界声明（明确不做）

- ❌ 不修改现有 skill
- ❌ 不修改现有文档体系（docs/thinking/ 是增量）
- ❌ 不做自动触发机制（先验证手动调用价值）
- ❌ 不做生命周期管理自动化（手动归档即可）
- ❌ 不做反馈回路（方向 4，作为第二阶段）

### 验证标准

- 在 2 周内至少做 3 次深度思考（L1 或 L2）
- 至少 1 次 thinking 产物被下游 skill 引用
- 用户主观评价：思考质量是否明显提升（1-5 分）

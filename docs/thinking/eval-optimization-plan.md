# Forge Eval 体系优化方案（goal 合约）

> 来源：`docs/thinking/eval-red-team-report.md` + designed/verified fixes 的 skeptic 裁定。
> 失效条件：若 eval 重构使本文引用的 file:line 不再适用，本方案随之失效；实施前以当前代码复核。

## Goal

把 Forge eval 体系从"证明 Forge 像 Forge"的自洽循环改造为"行为有效、盲评、非自指"的评测。具体：Forge arm 不再被喂 oracle 答案（`run-skills-benchmark.mjs:171-179`）；篡改证明层不再被 echo 击穿（`evidence-collector.mjs:203-212,227-230,238-243`）；自报 pass 不再等价于独立 pass 计分（`evaluate-skills/index.mjs:173-176` 忽略 `result.source`、`:47-56` fair 模型保留 25% Forge-schema `decisions` 轴、`:194-197` artifacts 走自报 `artifactCompletenessScore`）；2.0x 门不再由两个自选 n=1 案例或 `Infinity` 自动通过撑起（`index.mjs:79,268-274,314`；`CU-20260626-skill-effect-token-budget.md:64`）；"honest metric / 效果+100% / token-50%"不再是改名与阈值挪动的品牌包装（`measure-char-footprint.mjs:10-12`、`validate.mjs:177-191`、`CU-20260626-skill-effect-token-budget.md:9,11,12`）。

**主判据（master gate）**：一份手写答案回声 report（用 `tests/skills-suite-evaluation.test.mjs:15-45` 的 `reportEvidenceFor` 构造）+ 空/echo-only 的 `events.jsonl`，在默认信任下（无 `--trust-self-report`）必须 FAIL 掉 `evaluate-skills.mjs` 硬门。这恰是当前 `tests/skills-suite-evaluation.test.mjs:269-295` 断言 PASS `100/100 (A)` + `report passed` 的那条路径——直到该断言被反转为 FAIL，没有任何 finding 被真正关闭。

## Non-goals（边界）

- **不在本方案**：C3 validator `gate_owner` 真锚点解析（红队 Critical，designed set 未覆盖；`validate.mjs:541-548` 仅正则）——单独 CU。
- **不在本方案**：H1 `pass_rate` 从 oracle 裁决派生（`index.mjs:261-265,454,461`；Forge 强制 100%、baseline 自报不被质疑，`pass_rate_not_worse` 近 no-op）——fold 进 C2 follow-up 或单独 CU。
- **不在本方案**：`sanitizeNoForgeFixture` 截断/剥行非对称（`benchmark-helpers.mjs:30-54` 在 `实现要求：`/`Expected behavior:` 处截断，丢"跑 `node --test`"等产品/验证指令，`/skill/i` `/trigger/i` 剥范围约束行）——红队 finding #3，designed set 未覆盖；在它被修前 baseline 仍被结构性削弱，单独 CU。
- **不在本方案（需真实 run）**：全 suite 2.0x 经验主张、Codex seed/temperature flag 真实验证——P3 单独 CU。

## 关键诚实声明

1. **designed set 缺 C2-source-weighting**：红队 Critical #1（自报即得分）的真正修复不在 12 个 designed fix 中。SP-gate 的 refinement 提到它但标为 out-of-scope。本方案把它提升为 P0 命门 `C2-source-weighting`——否则 `tests/skills-suite-evaluation.test.mjs:269-295` 的 answer-echo=100/100 不可能被反转，主判据不成立，所有其它 fix 都是表面移动。

3. **多数 designed fix 单发只 partially 关闭**其 finding（一个通道）；只有 P0 cluster（盲 prompt + de-coach + echo 硬化 + source 加权 + 反转测试）合力才 fully 关闭红队 C1。CU/docs 不应在 P0 cluster 落地前宣称任何 finding 关闭。

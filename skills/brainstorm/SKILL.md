# Brainstorm — 探索阶段
## 职责
展开可能性空间，防止过早收敛到第一个想到的方案。
**核心洞察**：brainstorm 最大的敌人不是"没有好点子"，而是"太快收敛到显而易见的答案"。
**方法论**：自适应轮次——简单问题 1 轮，复杂问题多轮循环。

## 执行纪律

- **D3**：方向选择和 MVP 定义等关键分歧点停下来呈现选项，等人类确认
- **D6**：每个方向列出核心假设，假设不成立时向人类确认
- **D1**：被拒方向记录理由，未来条件变化时可重新评估

## 方法论：三轮循环
每一轮 brainstorm 是 3 个阶段的循环：
### 阶段 1: 理解问题（Understand）
在讨论方案之前，先确保对问题的理解足够深。
**核心问题**：
- 这个问题到底在影响谁？怎么影响的？
- 当前怎么解决的？现有方案的真正不足是什么？
- 追问 5 层"为什么"——用户说的痛点和真正的痛点经常不一样
**不变原则**：
- 先理解问题再想方案——跳到方案太快是 brainstorm 最常见的失败
- 痛点要具体到能讲出一个真实的场景（不是"效率低"，是"每周花 3 小时手动复制数据"）
- 如果 5 分钟后还没碰到让你意外的信息，说明理解还不够深
### 阶段 2: 展开方向（Expand）
从问题出发，展开尽可能多的可能性。
**核心问题**：
- 有哪些可能的方向？（至少 3 个，包含至少 1 个"看起来疯狂"的）
- 其他行业/领域怎么解决类似问题的？
- 如果没有任何限制，理想方案是什么？
**不变原则**：
- 发散时不评判——"这个不行"留到收敛阶段再说
- 每个方向要有"什么场景下它是对的"——没有绝对的好坏，只有适用场景
- 被拒方向要记录理由——未来条件变化时可能重新启用
### 阶段 3: 收敛验证（Converge & Validate）
从展开的方向中筛选最有潜力的，验证最强的假设。
**核心问题**：
- 哪个方向最值得深入？为什么？
- 这个方向最强的假设是什么？怎么最便宜地验证？
- 验证结果会不会改变我们对问题的理解？
**不变原则**：
- 评估标准先于评估——先定标准，再打分，避免凭感觉
- 验证要便宜且快速——访谈 > 原型 > 完整产品
- 决策标准提前定——"什么情况下继续、什么情况下停止"
### 自适应：是否需要下一轮？
| 信号 | 行动 |
|------|------|
| 验证发现假设不成立 | 回到阶段 1 重新理解问题 |
| 收敛时发现新的可能性 | 回到阶段 2 展开 |
| 方向清晰、假设可验证 | 结束，进入下一步 |
简单问题（方向已有直觉）：1 轮。复杂问题（方向不确定）：2-3 轮。
## AI 的角色：阶段切换
AI 在不同阶段扮演不同角色，主动推进探索而不是被动回答：
| 阶段 | AI 角色 | 行为 | 例子 |
|------|---------|------|------|
| 理解 | 思维挑战者 | 挑战假设、追问根因、指出盲区 | "为什么要做工具而不是改变流程？" |
| 展开 | 信息搜索者 | 搜索竞品、方案、跨领域案例 | "Notion 用 block 解决了类似问题" |
| 收敛 | 现实检验者 | 压力测试假设、指出风险 | "如果用户不愿付费，这个方向还成立吗？" |
## 决策点

> Brainstorm 使用 B# 前缀（Brainstorm Decision）。B# 记录在 idea-brief.md 中。
> 项目级共享决策使用 PD# 前缀。

### B1: 痛点探索（理解阶段）
**问**：当前怎么解决的？最让人头疼的是什么？如果只能解决一个痛点，解决哪个？
**记录**：核心痛点 + 现有方案 + 改进空间 + 根因分析
### B2: 可能性展开（展开阶段）
**问**：想过哪些方向？有没有参考产品？如果没有任何限制，理想方案是什么？
**记录**：方向列表（3-5 个）+ 各自的核心思路
### B3: 方向评估（收敛阶段）
**问**：各自解决哪些痛点？哪个最符合团队能力？哪个最容易验证？
**记录**：方向对比矩阵 + 推荐方向 + 推荐理由
### B4: 边界探索（收敛阶段）
**问**：有哪些变体？哪些是核心，哪些是锦上添花？如果只能做一个功能？
**记录**：核心功能清单 + 边界声明 + MVP 定义
### B5: 下一步行动（验证阶段）
**问**：需要验证哪些假设？谁来决定是否继续？验证成功后的下一步是什么？
**记录**：假设清单 + 验证计划 + 决策标准 + 下一步行动
## 引导技巧
**6 种技巧**：5 Whys（追问根因）· 极端场景（"1 人 vs 100 万用户"）· 类比思维（跨领域借鉴）· 反转思维（"什么一定失败"）· 约束加减法（"预算无限？只有 1 周？"）· AI 挑战（"为什么不做 X？"）
**深入信号**：出现新洞察、假设被推翻、方向间有未解决的分歧
**前进信号**：方向已排序、核心假设明确、MVP 可定义

### 迭代合并（每轮结束时执行）

当 brainstorm 进行多轮探索时，新一轮可能推翻或修改前一轮的结论。**合并规则**：

1. **替换**：用本轮最终结论替换前一轮对应段落。只保留最终版本的：
   - MVP 定义
   - 假设清单
   - 下一步行动
   - 推荐方向 + 评估矩阵

2. **压缩**：前一轮被推翻的结论压缩为「已评估方向」表格的一行：
   ```markdown
   | 方向 | 综合评分 | 一句话理由 |
   ```
   不保留被推翻结论的完整段落。

3. **标注**：最终产出的每个结论段标注来源轮次（如"（第4轮更新）"），让读者知道这是最新版。

4. **去重**：全文搜索重复段落（特别是 MVP、假设、行动），只保留最新版。

**最终 idea-brief.md 中同一段落（MVP / 假设 / 行动 / 推荐方向）只出现一次。**

## 文档约束
**idea-brief.md 必须包含**：核心痛点 · 方向地图（3-5 个）· 推荐方向+理由 · MVP 定义 · 假设清单+验证计划 · 决策标准 · 下一步行动
**idea-brief.md 不应包含**：技术选型（init 阶段）· 详细功能列表（define 阶段）· 交互设计（design 阶段）· 代码（生成代码）
## 模板
使用 `${CLAUDE_SKILL_DIR}/references/idea-brief-template.md` 作为产出结构参考。
idea-brief.md 的三个核心结构（详见模板）：
1. **方向对比矩阵** — 方向 × 维度（核心思路、适用场景、风险、验证难度）
2. **MVP 定义** — 核心功能 + 边界声明 + 验证标准
3. **假设清单** — 假设 × 验证方法 × 成功标准 × 负责人 × 时间
## 入口/出口条件
**入口**：用户有模糊想法或痛点，尚未明确方向
**出口**：生成 idea-brief.md + 推荐方向 + 验证计划，用户确认进入 init 阶段

**缺失处理**：
- 用户无痛点/无方向 → 降级为开放式探索（"你现在最想解决什么问题？"），不生成 idea-brief
- 用户已有完整方向 → 跳过 brainstorm，建议进入 init 或 define
- 用户只想聊不想产出 → 尊重节奏，但在对话结束时问"需要我把讨论整理成 idea-brief 吗？"
## 运行时信号
- 输入：user uncertainty
- 输出：validated direction、assumption list
- 路由：详见 `registry.yaml` 的 `forge-brainstorm` 节点；本节只保留人类可读摘要。
- 升级：方向无法排序 · 核心痛点无法具体化
## 何时不使用
- 方向已经明确（跳过 brainstorm，直接进入 init 阶段）
- 只是技术实现问题（直接进入 detail 阶段）
- 已有完整的 PRD（直接进入 detail 阶段，或需要交互设计时进入 design 阶段）
## 红旗清单
- 用户说"我们想做一切" → 强制收敛到 1 个核心痛点（"发散之前先定焦点"）
- 所有方向都"差不多" → 强制排序（"如果只能选一个呢？"）
- 用户跳过发散直接收敛 → 拉回发散，至少展开 3 个方向
- 过早评判 → 制止（"发散阶段先记下来，评估时再判断"）
- 痛点太抽象 → 追问具体例子（"能描述一个真实的场景吗？"）
- 没有验证计划 → 补充（"怎么知道这个方向是对的？"）
- MVP 太大 → 砍到"没有它就不成立"的最小集合
- 所有方向都很常规 → 加 1 个疯狂选项（"如果预算无限，你会怎么做？"）
- AI 挑战后用户完全不回应 → 可能还没理解够深，回到阶段 1
## 验证清单
- [ ] 痛点是否具体到能讲出真实场景？
- [ ] 是否展开了至少 3 个方向？
- [ ] 每个方向是否有"什么场景下它是对的"？
- [ ] 是否有方向对比矩阵 + 推荐方向 + 理由？
- [ ] MVP 是否小到可以在 2 周内验证？
- [ ] 是否有可执行的验证计划？
- [ ] 是否有明确的决策标准（继续/停止）？
- [ ] 下一步行动是否具体到"谁、做什么、什么时候"？
- [ ] 是否经过了 AI 挑战（思维惯性被打破）？
- [ ] **去重**：MVP 定义、假设清单、下一步行动是否各只出现一次（最终版本）？
- [ ] **去重**：被推翻的结论是否已压缩为「已评估方向」表格行，而非保留完整段落？
## 历史维护（自动）
完成后自动执行，不需要人工触发：
1. **追加 docs/timeline.md**（如不存在则创建）：
   ```markdown
   ### {日期} — {主题} 探索
   - 产出：idea-brief.md（{N} 个方向，{M} 轮探索，推荐：{方向名}）
   ```
2. **更新 docs/status.md**（如不存在则从模板创建）：
   - 新 feature → 添加行，⓪探索 → `✅`
   - 已有 feature → 更新 ⓪探索 列为 `✅`
3. **检查膨胀**：timeline.md 超过 100 行时，旧记录归档到 `timeline/`。

# Decision Presentation — 决策呈现规则

> 全局规则：AI 在 skill 决策点向用户呈现选择时，使用 AskUserQuestion 工具而非自然语言提问。

## 核心原则

**先研究，再呈现。** AI 不是把选项甩给用户，而是先搜索/分析/推导，然后把收敛后的 2-4 个选项用结构化方式呈现，让用户做选择。

**选择 > 填空。** 能给出选项让用户点选的，不要用自然语言让用户从零开始写。

## 什么时候用 AskUserQuestion

选项可枚举时——用户需要在 2-4 个明确方案之间做选择。

**适用场景**（跨所有 skill）：

| 场景 | 例子 |
|------|------|
| 技术选型 | 框架选 Next.js 还是 Hono？ |
| 策略选择 | 分页选 page 还是 cursor？ |
| 范围决策 | 多租户这个版本做不做？ |
| 方向选择 | brainstorm 收敛时推荐方向 A 还是 B？ |
| 参数确认 | 帧率目标 30fps 还是 60fps？ |
| 流程分支 | 先做 API 详设还是先做前端详设？ |

**呈现格式**：

```
AskUserQuestion({
  question: "状态管理选什么方案？",
  header: "状态管理",
  options: [
    { label: "Zustand (Recommended)", description: "轻量、简单、适合中小项目" },
    { label: "Redux Toolkit", description: "成熟生态、适合大型项目、DevTools 强" },
    { label: "Jotai", description: "原子化、适合细粒度状态、React 18 原生" }
  ],
  multiSelect: false
})
```

**标记规则**：
- 推荐方案标 `(Recommended)`
- 每个选项一句话说明代价或适用场景
- 用户始终可以选 Other 输入自定义方案

## 什么时候用自然语言

选项不可枚举时——需要用户描述场景、展开思维、提供上下文。

**适用场景**：

| 场景 | 例子 |
|------|------|
| 开放式探索 | "你的用户是谁？他们最痛的点是什么？" |
| 场景描述 | "描述一个真实的使用场景" |
| 发散思维 | "有没有想过完全不同的方向？" |
| 上下文收集 | "这个功能的数据量大概多大？" |
| 发散阶段 | brainstorm 的理解和展开阶段 |

## Skill 决策点中的判断

每个 skill 的决策点（`### XX: 主题`）都有 `**问**` 和 `**记录**`。判断方法：

| 决策点特征 | 呈现方式 |
|-----------|---------|
| `**问**` 是在几个方案间选择 | AskUserQuestion |
| `**问**` 是开放描述 | 自然语言 |
| `**不变原则**` 里有明确的 A > B 排序 | AskUserQuestion（A 标 Recommended） |
| 需要先搜索/推导才有选项 | 先研究，再用 AskUserQuestion |

**混合模式**：一个决策点可能先用自然语言收集上下文，再用 AskUserQuestion 呈现选项。

```
AI: "这个项目大概多少 API 调用？有实时推送需求吗？"（自然语言）
用户: "大概 50 个端点，需要 WebSocket"
AI: AskUserQuestion({ question: "数据请求方案选什么？", ... })（结构化选择）
```

## 执行顺序

1. **读决策点**：理解 `**问**` 和 `**不变原则**`
2. **研究/推导**：根据上下文搜索方案、分析利弊
3. **收敛选项**：筛选出 2-4 个最值得推荐的方案
4. **呈现选择**：用 AskUserQuestion 结构化呈现
5. **记录决策**：把用户选择 + 理由 + 被拒方案写入产物文档

# Brainstorm — 探索阶段

## 职责

引导用户在模糊阶段展开可能性空间，从"想做个东西"到"这个方向值得深入"。

**原则**：先发散再收敛。发散阶段不评判、不决策、不承诺。

## 决策点

### B1: 痛点探索

**问**：
- 当前用户怎么解决这个问题的？
- 现有方案最让人头疼的是什么？
- 如果只能解决一个痛点，解决哪个？

**记录**：核心痛点 + 现有方案 + 改进空间

### B2: 可能性展开

**问**：
- 想过哪些方向来解决这个问题？
- 有没有参考的产品或方案？
- 如果没有任何技术限制，理想的方案是什么？

**记录**：方向列表（3-5 个）+ 各自的核心思路

### B3: 方向评估

**问**：
- 这些方向各自解决哪些痛点？
- 哪个方向最符合团队的能力？
- 哪个方向最容易验证？

**记录**：方向对比矩阵 + 推荐方向 + 推荐理由

### B4: 边界探索

**问**：
- 这个方向有哪些变体？
- 哪些功能是核心，哪些是锦上添花？
- 如果只能做一个功能，做哪个？

**记录**：核心功能清单 + 边界声明 + MVP 定义

### B5: 下一步行动

**问**：
- 需要验证哪些假设？
- 谁来决定是否继续？
- 验证成功后的下一步是什么？

**记录**：假设清单 + 验证计划 + 决策标准 + 下一步行动

## 文档约束

**idea-brief.md 必须包含：**
1. 核心痛点（具体、可验证）
2. 方向地图（3-5 个方向 + 各自适用场景）
3. 推荐方向 + 推荐理由
4. MVP 定义（核心功能 + 边界）
5. 假设清单 + 验证计划
6. 决策标准（什么情况下继续/停止）
7. 下一步行动（谁、做什么、什么时候）

**idea-brief.md 不应包含：**
- 具体技术选型（那是 /forge-init 的事）
- 详细功能列表（那是 /forge-define 的事）
- 交互设计（那是 /forge-design 的事）
- 代码实现（那是 生成代码 的事）

## 模板

使用 `${CLAUDE_SKILL_DIR}/references/idea-brief-template.md` 作为产出结构参考。

## 恒久约定

### 方向地图格式
```markdown
## 方向对比

| 方向 | 核心思路 | 适用场景 | 风险 | 验证难度 |
|------|---------|---------|------|---------|
| A | ... | ... | ... | 低/中/高 |
| B | ... | ... | ... | 低/中/高 |
| C | ... | ... | ... | 低/中/高 |
```

### MVP 定义格式
```markdown
## MVP 定义

**核心功能**（必须有）：
- 功能 1：...
- 功能 2：...

**边界声明**（明确不做）：
- 不做 X，因为...
- 不做 Y，因为...

**验证标准**：
- 用户能在 Z 分钟内完成核心任务
- 用户反馈满意度 > 7/10
```

### 假设清单格式
```markdown
## 假设清单

| 假设 | 验证方法 | 成功标准 | 负责人 | 时间 |
|------|---------|---------|--------|------|
| 用户愿意用 X | 访谈 5 个目标用户 | 4/5 表示会用 | 张三 | 1 周 |
| Y 方案技术可行 | PoC 验证 | 性能达标 | 李四 | 2 周 |
```

## 入口/出口条件

**入口条件**：
- 用户有一个模糊的想法或痛点
- 尚未明确具体方向

**出口条件**：
- 生成了 idea-brief.md
- 有明确的推荐方向 + 理由
- 有可执行的验证计划
- 用户确认是否继续（进入 /forge-init）

## 何时不使用

- 方向已经明确（跳过 brainstorm，直接进入 /forge-init）
- 只是技术实现问题（直接进入 /forge-detail）
- 已有完整的 PRD（直接进入 /forge-design）

## 红旗清单

- 用户说"我们想做一切" → 强制收敛到 1 个核心痛点
- 所有方向都"差不多" → 强制用户排序，问"如果只能选一个呢？"
- 用户跳过发散直接收敛 → 拉回发散阶段，至少展开 3 个方向
- 没有验证计划 → 补充"怎么知道这个方向是对的？"
- MVP 太大 → 强制砍到"没有它就不成立"的最小集合

## 验证清单

- [ ] 核心痛点是否具体、可验证？
- [ ] 是否展开了至少 3 个方向？
- [ ] 每个方向是否有清晰的"适用场景"？
- [ ] 是否有明确的推荐方向 + 理由？
- [ ] MVP 是否小到可以在 2 周内验证？
- [ ] 是否有可执行的验证计划？
- [ ] 是否有明确的决策标准（继续/停止）？
- [ ] 下一步行动是否具体到"谁、做什么、什么时候"？

## 完成提示

完成后向用户展示：

```
✅ 探索完成！idea-brief.md 已生成。

下一步你可以：
  /forge-init    — 初始化项目（业务对齐 + 技术选型 + 设计系统）
  继续探索       — 对某个方向深入 brainstorm
  自然语言       — 直接说"做任务管理系统"跳过初始化
```

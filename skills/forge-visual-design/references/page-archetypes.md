# Page Archetypes — 页面类型模型

不是模板，是结构选择器。根据内容目标和用户任务选择页面类型，再从类型推导布局和组件。

## 类型总览

| 类型 | 用户目标 | 信息密度 | 默认结构 |
|------|---------|---------|---------|
| Explainer | 理解概念 | 中 | Hero → 核心观点 → 模型 → 示例 → FAQ |
| Product | 了解/购买 | 中低 | 痛点 → 方案 → 流程 → 证明 → CTA |
| Dashboard | 监控/操作 | 高 | 指标 → 趋势 → 明细 → 操作 |
| Docs | 学习/查阅 | 高 | 导航 → 概念 → API → 示例 |
| Report | 分析/决策 | 高 | 摘要 → 发现 → 证据 → 建议 |
| Comparison | 对比选择 | 中高 | 标准 → 表格 → 评分 → 推荐 |
| Landing | 转化 | 低 | Hero → 价值主张 → 社会证明 → CTA |
| Form | 数据录入 | 中 | 步骤 → 字段 → 验证 → 提交 |

---

## Explainer — 解释复杂概念

- **用户目标**：理解一个概念、模型或方法
- **默认结构**：Hero（一句话定义）→ 核心观点（2-3 个）→ 模型/图示 → 具体示例 → FAQ
- **推荐布局**：Split Layout、Timeline
- **核心组件**：Hero、Callout、DiagramBox、CodeBlock、FAQ
- **关键判断**：概念是否需要图示？是否需要和已知概念对比？

## Product — 产品介绍

- **用户目标**：了解产品能解决什么、怎么解决、是否值得用
- **默认结构**：Hero（价值主张）→ 痛点共鸣 → 解决方案 → 工作流程 → 社会证明 → CTA
- **推荐布局**：Hero+Cards、Bento Grid
- **核心组件**：Hero、Card、CTA、Metric、Badge
- **关键判断**：产品截图能否替代装饰图？用户需要先看功能还是先看价格？

## Dashboard — 数据展示

- **用户目标**：快速了解状态、发现异常、执行操作
- **默认结构**：核心指标（3-5 个）→ 趋势图 → 明细表 → 快捷操作
- **推荐布局**：Metric Grid + Table
- **核心组件**：Metric、Card、ComparisonTable、Badge、CTA
- **关键判断**：数据需要实时还是定期刷新？异常如何高亮？

## Docs — 技术文档

- **用户目标**：学习概念、查阅 API、复制示例代码
- **默认结构**：侧边导航 → 概念解释 → API 参考 → 代码示例
- **推荐布局**：Sidebar + Content
- **核心组件**：Section、CodeBlock、Callout、Card（用于概念卡片）
- **关键判断**：读者是从头学还是跳查？代码示例是否需要可运行？

## Report — 研究报告

- **用户目标**：获取结论、验证证据、做出决策
- **默认结构**：执行摘要 → 关键发现 → 支撑证据 → 建议/下一步
- **推荐布局**：Split Layout、Timeline
- **核心组件**：Callout（用于结论）、Metric、ComparisonTable、Section
- **关键判断**：读者先看结论还是先看数据？证据是否需要可下载？

## Comparison — 方案对比

- **用户目标**：在多个选项中做出选择
- **默认结构**：评估标准 → 对比表格 → 评分/排名 → 推荐结论
- **推荐布局**：Comparison Table
- **核心组件**：ComparisonTable、Badge、Callout（用于推荐）、Metric
- **关键判断**：对比维度是否可量化？是否需要"我们推荐"还是只呈现事实？

## Landing — 营销转化

- **用户目标**：被说服、产生信任、采取行动
- **默认结构**：Hero（强主张）→ 价值点（3 个）→ 社会证明 → CTA
- **推荐布局**：Hero+Cards
- **核心组件**：Hero、Card、CTA、Metric（数据证明）、Badge
- **关键判断**：主 CTA 是什么？页面只有一个核心行动

## Form — 数据录入

- **用户目标**：高效准确地完成信息提交
- **默认结构**：步骤指示 → 表单字段 → 实时验证 → 提交确认
- **推荐布局**：Step-by-step Flow
- **核心组件**：Section（字段分组）、Callout（错误提示）、CTA（提交）、Badge（步骤状态）
- **关键判断**：字段数量是否需要分步？验证是实时还是提交后？

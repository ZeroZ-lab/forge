# Visual Design — 设计阶段（视觉层）

## 职责

建立设计系统，确保产品在视觉上系统化一致。不是每个页面单独设计，而是建立系统后消费。

**原则**：一致性 > 创意。设计系统 > 单页面设计。留白是最强的设计工具。

## 决策点

### V1: 色彩系统

**问**：
- 有品牌指南吗？
- 产品的气质是什么？（专业、活泼、极简、温暖）
- 需要支持暗色模式吗？

**不变原则**：
- 主色不超过 3 个（主色、辅助色、强调色）
- 色彩要有语义（成功=绿、警告=黄、错误=红、信息=蓝）
- 对比度要符合 WCAG 标准（文本至少 4.5:1）

**记录**：色板（主色、辅助色、语义色、中性色）+ 暗色模式变体

### V2: 字体系统

**问**：
- 有品牌字体吗？
- 需要支持多语言吗？（中文、英文、日文）
- 字体加载策略是什么？（系统字体 vs Web Font）

**不变原则**：
- 字体层级要清晰（标题、正文、辅助文本）
- 行高要舒适（1.5-1.8 倍）
- 字体大小要符合阅读习惯（正文至少 14px）

**记录**：字体家族 + 字体层级 + 行高规则

### V3: 间距系统

**问**：
- 产品的节奏感是什么？（紧凑 vs 宽松）
- 需要响应式间距吗？（移动端 vs 桌面端）
- 间距的基准单位是什么？（4px、8px）

**不变原则**：
- 间距要有规律（4px 基准网格）
- 间距要分层（组件内、组件间、区块间）
- 留白是设计工具，不是浪费

**记录**：间距规范（基准单位 + 层级 + 响应式规则）

### V4: 组件库

**问**：
- 需要哪些基础组件？（按钮、输入框、卡片、表格）
- 组件需要支持哪些状态？（默认、悬停、聚焦、禁用、加载）
- 组件的尺寸变体有哪些？（small、medium、large）

**不变原则**：
- 组件要有明确的职责边界
- 组件状态要完整（不要漏掉禁用、加载状态）
- 组件组合要有规则

**记录**：组件清单 + 状态定义 + 尺寸变体 + 组合规则

### V5: 设计 Token

**问**：
- 设计 Token 的命名规范是什么？
- 需要支持多主题吗？
- Token 如何与代码同步？

**不变原则**：
- Token 命名要语义化（color-primary 不是 color-blue）
- Token 要分层（全局 Token → 别名 Token → 组件 Token）
- Token 要与代码同步（设计系统 = 单一真相源）

**记录**：Token 结构 + 命名规范 + 同步策略

## 文档约束

**DESIGN.md 必须包含：**
1. 色彩系统（色板 + 暗色模式 + 语义色）
2. 字体系统（字体家族 + 层级 + 行高）
3. 间距系统（基准单位 + 层级 + 响应式）
4. 组件库（基础组件 + 状态 + 变体）
5. 设计 Token（结构 + 命名 + 同步策略）
6. 图标系统（图标库 + 尺寸 + 风格）
7. 动效规范（过渡时长 + 缓动函数 + 使用场景）

**DESIGN.md 不应包含：**
- 交互设计（那是 interaction-design 的事）
- 具体页面设计（那是 interaction-design 的事）
- 代码实现（那是 /forge-detail 的事）

## 恒久约定

### 色彩系统格式
```markdown
## 色彩系统

### 主色
- Primary: #2563EB（蓝色）
- Secondary: #7C3AED（紫色）
- Accent: #F59E0B（橙色）

### 语义色
- Success: #10B981（绿色）
- Warning: #F59E0B（黄色）
- Error: #EF4444（红色）
- Info: #3B82F6（蓝色）

### 中性色
- Gray-50: #F9FAFB
- Gray-100: #F3F4F6
- ...
- Gray-900: #111827

### 暗色模式
- 背景：Gray-900
- 文本：Gray-50
- 边框：Gray-700
```

### 字体系统格式
```markdown
## 字体系统

### 字体家族
- 中文：PingFang SC, Microsoft YaHei
- 英文：Inter, -apple-system
- 代码：Fira Code, monospace

### 字体层级
- H1: 32px / 700 / 1.2
- H2: 24px / 600 / 1.3
- H3: 20px / 600 / 1.4
- Body: 16px / 400 / 1.5
- Small: 14px / 400 / 1.5
- Caption: 12px / 400 / 1.4
```

### 设计 Token 格式
```markdown
## 设计 Token

### 全局 Token
```
--color-blue-500: #2563EB
--spacing-4: 16px
--font-size-base: 16px
```

### 别名 Token
```
--color-primary: var(--color-blue-500)
--spacing-base: var(--spacing-4)
--font-size-body: var(--font-size-base)
```

### 组件 Token
```
--button-bg-primary: var(--color-primary)
--button-padding: var(--spacing-base)
--button-font-size: var(--font-size-body)
```
```

## 入口/出口条件

**入口条件**：
- 有 interaction-spec.md（来自 /interaction-design）
- 或用户已有交互设计（跳过 interaction-design）

**出口条件**：
- 生成了 DESIGN.md
- 设计系统已建立（色彩、字体、间距、组件）
- 设计 Token 已定义（结构 + 命名）
- 用户确认是否继续（进入 /forge-detail）

## 何时不使用

- 纯后端 API（没有用户界面）
- 已有完整的设计系统（直接进入 /forge-detail）
- 内部工具，不需要精美设计（简化视觉流程）

## 红旗清单

- 主色超过 3 个 → 强制收敛（"哪个是主色？"）
- 对比度不符合 WCAG → 强制调整（"文本至少 4.5:1"）
- 间距没有规律 → 强制使用基准网格（"4px 还是 8px？"）
- 组件状态不完整 → 强制补充（"禁用、加载状态呢？"）
- Token 命名不语义化 → 重写（"color-primary 不是 color-blue"）

## 验证清单

- [ ] 色彩系统是否完整（主色、语义色、中性色）？
- [ ] 对比度是否符合 WCAG 标准？
- [ ] 字体层级是否清晰（标题、正文、辅助）？
- [ ] 间距是否有规律（基准网格）？
- [ ] 组件库是否完整（基础组件 + 状态 + 变体）？
- [ ] 设计 Token 是否语义化命名？
- [ ] 是否支持暗色模式（如需要）？

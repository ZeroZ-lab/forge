# Visual Design — 设计阶段（视觉层）

## 职责

建立设计决策系统——教 AI 做设计判断，不是填模板。

**核心洞察**：好的视觉设计 = 内容目标 → 页面类型 → 布局模式 → 组件组合 → 视觉风格。AI 味的根源是跳过前面的判断直接选颜色和组件——结果永远是 Material/Ant 默认值。

**方法论**：发现 → 意图 → 页面判断 → 视觉选择 → 验证 → 预览。

**Mobile-First 原则**：所有设计决策从最小屏幕开始，逐步增强到桌面。60%+ 流量来自移动端，Google 已全面移动优先索引。Mobile-first 不是断点策略，是设计方法论——先决定什么最重要（空间有限时被迫做减法），再决定桌面端怎么增强。

## 与上下游的边界

**上游**：读 interaction-spec（交互规格），知道页面结构和组件行为
**下游**：DESIGN.md 交给 /forge-detail（前端实现）和代码生成

**和 interaction-design 的切法**：
- interaction 定义**组件做什么**（行为、组合规则、交互模式）
- visual 定义**组件长什么样**（外观、色彩、间距、状态样式）+ **页面怎么组织**（类型、布局、组件组合）

## 方法论

### 第一步：发现（Discover）

**AI 行为**：搜索并结构化提取，不是随便浏览。

**搜索提取框架**（每个参考设计系统提取以下维度）：
- 色彩：几个主色？语义色怎么分？暗色模式怎么做？
- 间距：基准单位？层级规律？
- 字体：几个层级？行高规则？display tracking？
- 组件模式：状态怎么表达？变体怎么组织？

**对比分析**：3 个系统都做了 = 行业共识 · 只有 1 个做了 = 可能是特色 · 都没做 = 可能不需要

**不变原则**：不是抄，是了解 landscape 后做有意识选择 · 参考 3-5 个设计系统 · 好的参考不只是"好看"，是"为什么这样选择"

**AI 搜索源**：Material、Ant、Chakra、Radix、Shadcn、Primer（GitHub）、Carbon（IBM）、Polaris（Shopify）· 品牌案例：Smashing Magazine、Refactoring UI · Token 标准：W3C Design Tokens、Style Dictionary

### 第二步：定意图（Intent）

视觉设计从产品气质开始，不是从色号开始。

**核心问题**：
- 3-5 个形容词描述气质（"克制的科技感"不是"好看"）
- 气质从哪来？（品牌定位？目标用户？产品功能？）
- 有品牌指南吗？需要暗色模式？多平台？

**不变原则**：
- 气质决定一切——色彩、字体、间距都从气质推导
- 意图要具体到能验证——"克制" = 低饱和度 + 等宽字体 + 大留白
- 推导链格式：`气质 → 选择 → 理由`

### 第三步：页面判断（Page Judgment）

在选颜色之前，先决定页面怎么组织。

**3.1 页面类型**：读 `references/page-archetypes.md`，根据内容目标选择类型
**3.2 布局模式**：读 `references/layout-patterns.md`，从页面类型推导布局
**3.3 组件组合**：读 `references/component-grammar.md`，从布局选择组件

**不变原则**：
- 内容决定布局，布局决定组件，组件决定样式
- 每个选择都要有理由（"为什么用 Bento Grid 而不是 Split？"）
- 页面没有明确类型 = 设计还没想清楚

### 第四步：视觉选择（Choose）

从意图推导每个视觉选择。具体的 Token 值定义在 DESIGN.md 中（见 design-system-template.md），这里只记方法论。

**选择三件套**：色彩 + 字体 + 间距

**不变原则**：
- 主色 ≤ 3 · 色彩有语义（成功=绿、警告=黄、错误=红）· WCAG 对比度 4.5:1
- 字体层级清晰 · 行高 1.5-1.8 · 正文 ≥ 14px · display 字号用负 tracking
- 间距有规律（4px 基准网格）· 留白是设计工具不是浪费
- 克制优先："删掉它产品会变丑吗？"不会就不需要
- Token 命名语义化（color-primary 不是 color-blue）· Token 分层（全局 → 别名 → 组件）
- **移动端约束**：触控目标 ≥ 44×44pt（Apple）/ 48×48dp（Google）· 移动端正文 ≥ 16px · 断点从内容推导不从设备推导 · 表单单列 · 主 CTA 在拇指区（屏幕中下 1/3）

### 第五步：验证（Validate）

**反 AI 味检查清单**：
- 和 Material/Ant/Chakra 默认值对比——雷同则强制差异化
- 把主色换成蓝色，产品会失去辨识度吗？不会 = 选择不够有意图
- 设计系统能从产品气质推导出来吗？不能 = 选择是任意的
- 有没有刻意的"不完美"？完全对称 = AI 味
- 组件状态完整吗？（默认/悬停/聚焦/禁用/加载）

### 第六步：预览（Preview）

文字规格无法验证视觉感受——必须看到真实渲染。

**AI 行为**：从 DESIGN.md 生成 design-preview.html（单文件，零依赖，浏览器直接打开），包含色板、字体层级、间距系统、组件展示、页面布局示例。发现不协调 → 改 DESIGN.md → 重新生成预览。

## AI 的角色

| 阶段 | AI 角色 | 行为 |
|------|---------|------|
| 发现 | 设计搜索者 | 结构化提取参考系统的色彩/间距/字体/组件维度 |
| 意图 | 气质翻译者 | 把抽象气质翻译成具体视觉方向 |
| 页面判断 | 结构决策者 | 从内容目标选择页面类型→布局→组件 |
| 视觉选择 | 意图守护者 | 每个选择追问"这和气质有什么关系？" |
| 验证 | 反模板检查者 | 和默认值对比，指出雷同 |
| 预览 | 渲染生成者 | 生成 design-preview.html 验证视觉 |

## 决策点

### V1: 色彩系统
**问**：有品牌指南吗？产品气质？暗色模式？
**不变原则**：推导链（气质→色彩→理由） · 主色 ≤ 3 · 语义色 · WCAG 4.5:1
**记录**：色板 + 暗色变体 + 推导链

### V2: 字体系统
**问**：有品牌字体吗？多语言？加载策略？
**不变原则**：层级清晰 · 行高 1.5-1.8 · display 负 tracking · 正文 ≥ 14px
**记录**：字体家族 + 层级 + 行高规则 + 推导链

### V3: 间距系统
**问**：基准单位？响应式间距？移动端断点？
**不变原则**：4px 基准 · 有规律层级 · 留白是设计工具 · 断点从内容推导（不从设备推导）· 响应式 Token 和视觉 Token 分离
**记录**：基准 + 层级 + 响应式规则 + 断点策略

### V4: 页面结构
**问**：内容目标是什么？用户第一眼该看到什么？
**不变原则**：内容决定布局 · 每页有明确类型 · 布局选择有理由
**记录**：页面类型 + 布局模式 + 组件组合 + 选择理由

### V5: 组件外观 + Token
**问**：基础组件有哪些？状态？尺寸变体？Token 结构？
**不变原则**：从 Token 推导组件外观 · 状态完整 · Token 语义化命名 · 分层
**记录**：组件规范 + Token 结构 + 命名规范

## 文档约束

**DESIGN.md 必须包含**：产品气质+推导链 · 色彩系统 · 字体系统 · 间距系统 · 页面结构决策 · 组件库（外观+状态+变体）· 设计 Token · 参考设计系统
**DESIGN.md 不应包含**：交互设计（interaction-design）· 代码实现（/forge-detail）

## 红旗清单

- 色彩选择和气质无关 → 强制推导
- 和 Material/Ant 默认值雷同 → 强制差异化
- 主色超过 3 个 → 强制收敛
- 对比度不符合 WCAG → 强制调整
- 没有参考设计系统 → 强制搜索
- 每个选择都没有"为什么" → 强制推导
- 页面没有明确类型 → 强制判断（"这个页面是 Explainer 还是 Dashboard？"）
- 布局没有选择理由 → 强制解释（"为什么用 Bento 而不是 Split？"）
- 组件数量超出约束 → 强制精简
- 没有考虑移动端 → 强制检查（"触控目标够大吗？移动端怎么读？"）
- 桌面端布局直接缩放成移动端 → 强制 mobile-first（"先画手机端，再增强桌面端"）

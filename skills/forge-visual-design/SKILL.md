# Visual Design — 设计阶段（视觉层）

## 职责

建立有辨识度的视觉语言——每个选择都有意图，拒绝 AI 默认值。

**核心洞察**：AI 味的根源是"默认值"——AI 总是倾向于最常见的选择（蓝紫渐变、对称布局、过度干净）。好的设计不是填表，是一系列有意图的选择。每个选择都要能回答"为什么是这个而不是那个"。

**方法论**：发现→意图→选择→验证。

## 与上下游的边界

**上游**：读 interaction-spec（交互规格），知道页面结构和组件行为
**下游**：DESIGN.md 交给 /forge-detail（前端实现）和代码生成

**和 interaction-design 的切法**：
- interaction 定义**组件做什么**（行为、组合规则、交互模式）
- visual 定义**组件长什么样**（外观、色彩、间距、状态样式）

## 方法论：发现→意图→选择→验证

### 第一步：发现（Discover）

在做任何选择之前，先看看市面上有什么。

**核心问题**：
- 同类产品用了什么设计系统？
- 哪些设计系统/品牌设计值得参考？
- 有哪些成熟的 Design Token 体系可以借鉴？

**不变原则**：不是抄，是了解 landscape 后做有意识的选择 · 参考 3-5 个设计系统 · 好的参考不只是"好看"，是"为什么这样选择"

**AI 行为**：主动搜索——
- 开源设计系统：Material、Ant、Chakra、Radix、Shadcn、Primer（GitHub）、Carbon（IBM）、Polaris（Shopify）
- 品牌案例 + 设计博客：Smashing Magazine、Refactoring UI、Dribbble、Behance
- Design Token 标准：W3C Design Tokens Community Group、Style Dictionary、Figma Tokens

### 第二步：定意图（Intent）

视觉设计从产品气质开始，不是从色号开始。意图是所有视觉选择的根。

**核心问题**：
- 用 3-5 个形容词描述产品气质（不是"好看"，是"克制的科技感"或"温暖的工具感"）
- 气质从哪来？（品牌定位？目标用户？产品功能？）
- 有品牌指南吗？（有则是起点，没有则从气质推导）
- 需要支持暗色模式吗？多平台？

**不变原则**：
- 气质决定一切——色彩、字体、间距都从气质推导
- 品牌指南是起点不是约束
- 意图要具体到能验证——"克制的科技感"意味着低饱和度+等宽字体+大留白
- 暗色模式和多平台从一开始考虑

### 第三步：做选择（Choose）

从意图推导出每个视觉选择，每个选择都要有推导链。

**推导链格式**：`气质 → 选择 → 理由`

示例：
- "克制的科技感" → 主色 #1E293B（深灰蓝）+ 强调色 #3B82F6（蓝）→ 低饱和度传达克制，蓝色传达技术信任
- "温暖的工具感" → 主色 #92400E（暖棕）+ 强调色 #F59E0B（琥珀）→ 暖色调传达亲和力，琥珀传达效率

**选择三件套**：色彩 + 字体 + 间距

**不变原则**：
- 主色不超过 3 个 · 色彩有语义（成功=绿、警告=黄、错误=红）· 对比度符合 WCAG（4.5:1）
- 字体层级清晰 · 行高舒适（1.5-1.8 倍）· 正文至少 14px
- 间距有规律（4px 基准网格）· 留白是设计工具不是浪费

**克制优先**：每个新增颜色/字体/间距都要有理由 · "删掉它产品会变丑吗？"不会就不需要 · 3 色+3 级字体+5 级间距足够大多数产品

### 第四步：验证（Validate）

每个选择做完后，进行反 AI 味检查。

**反 AI 味检查清单**：
- 每个选择是否和默认/通用方案不同？（"为什么不用 Material 的默认蓝？"）
- 把主色换成蓝色，产品会失去辨识度吗？（如果不会，说明选择不够有意图）
- 设计系统是否能从产品气质推导出来？（如果不能，说明选择是任意的）
- 有没有刻意的"不完美"？（完全对称 = AI 味，刻意不对称 = 人工感）

**组件外观 + Token 化**：
- 组件外观从系统 Token 推导（不单独定义颜色）
- 组件状态要完整（默认/悬停/聚焦/禁用/加载）
- Token 命名语义化（color-primary 不是 color-blue）
- Token 分层（全局 → 别名 → 组件）

## AI 的角色

| 阶段 | AI 角色 | 行为 |
|------|---------|------|
| 发现 | 设计搜索者 | 搜索开源设计系统、品牌案例、Token 标准，呈现参考地图 |
| 意图 | 气质翻译者 | 把抽象气质翻译成具体视觉方向（"克制"→低饱和度+等宽字体+大留白） |
| 选择 | 意图守护者 | 每个选择都追问"这和气质有什么关系？"，拒绝无推导的选择 |
| 验证 | 反模板检查者 | 和 Material/Ant/Chakra 默认值对比，指出雷同 |

## 决策点

### V1: 色彩系统

**问**：有品牌指南吗？产品气质？暗色模式？

**记录**：色板（主色、辅助色、语义色、中性色）+ 暗色模式变体 + 每个色彩的推导链

### V2: 字体系统

**问**：有品牌字体吗？多语言？字体加载策略？

**记录**：字体家族 + 字体层级 + 行高规则 + 每个字体的推导链

### V3: 间距系统

**问**：产品节奏感？响应式间距？基准单位？

**记录**：间距规范（基准单位 + 层级 + 响应式规则）

### V4: 组件外观

**问**：需要哪些基础组件？状态？尺寸变体？

**记录**：组件清单 + 状态定义 + 尺寸变体 + 组合规则

### V5: 设计 Token

**问**：命名规范？多主题？与代码同步？

**记录**：Token 结构 + 命名规范 + 同步策略

## 文档约束

**DESIGN.md 必须包含**：产品气质+推导链 · 色彩系统 · 字体系统 · 间距系统 · 组件库（外观+状态+变体）· 设计 Token · 参考设计系统

**DESIGN.md 不应包含**：交互设计（interaction-design）· 页面设计（interaction-design）· 代码实现（/forge-detail）

## 模板

使用 `${CLAUDE_SKILL_DIR}/references/design-system-template.md` 作为产出结构参考。核心结构：
1. **产品气质** — 形容词 + 推导链
2. **色彩系统表** — Token × 值 × 用途 × 推导理由
3. **字体层级表** — Token × 大小 × 字重 × 行高 × 用途
4. **组件规范** — 变体 × 尺寸 × 状态

## 入口/出口条件

**入口**：有 interaction-spec.md（来自 interaction-design）或用户已有交互设计
**出口**：DESIGN.md 已生成 · 每个选择有推导链 · 通过反 AI 味检查 · 用户确认进入 /forge-detail

## 何时不使用

纯后端 API · 已有完整设计系统 · 内部工具不需要精美设计（简化流程）

## 红旗清单

- 色彩选择和气质无关 → 强制推导（"这个颜色和气质有什么关系？"）
- 和 Material/Ant 默认值雷同 → 强制差异化（"为什么不直接用 Material？"）
- 主色超过 3 个 → 强制收敛（"哪个是主色？"）
- 对比度不符合 WCAG → 强制调整（"文本至少 4.5:1"）
- 没有参考设计系统 → 强制搜索（"市面上有什么可以参考的？"）
- 每个选择都没有"为什么" → 强制推导（"为什么是这个颜色/字体/间距？"）
- 设计系统"太完美" → 加入刻意不完美（"哪些地方可以打破规则？"）

## 验证清单

- [ ] 产品气质是否具体到能推导视觉选择？
- [ ] 每个色彩/字体选择是否有推导链？
- [ ] 是否搜索并参考了 3-5 个设计系统？
- [ ] 是否通过了反 AI 味检查（和默认方案不同）？
- [ ] 对比度是否符合 WCAG 标准？
- [ ] 组件库是否完整（基础组件 + 状态 + 变体）？
- [ ] 设计 Token 是否语义化命名？
- [ ] 是否体现了克制（少即是多）？

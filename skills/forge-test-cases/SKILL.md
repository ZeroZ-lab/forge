# Test Cases — 测试阶段

## 职责

从详设文档（contract.md）的验收条件推导出完整的测试用例。

**原则**：测试用例 = 验收条件的可执行版本。每个验收条件都要有对应的测试。

## 决策点

### TC1: 测试范围

**问**：
- contract.md 里有哪些验收条件？
- 每个验收条件需要哪些测试？
- 测试的优先级是什么？

**不变原则**：
- 测试范围从验收条件推导，不是从代码推导
- 每个验收条件至少 1 个测试
- 核心功能优先（P0 > P1 > P2）

**记录**：测试范围矩阵（验收条件 → 测试用例）

### TC2: 正常路径

**问**：
- 每个功能的正常流程是什么？
- 预期的输入和输出是什么？
- 正常路径有哪些变体？

**不变原则**：
- 正常路径是测试的基础
- 每个正常路径至少 1 个测试
- 测试数据要真实（不是 "test123"）

**记录**：正常路径测试清单（输入 + 预期输出 + 验证点）

### TC3: 边界情况

**问**：
- 输入的边界值是什么？（空值、最大值、最小值）
- 状态的边界是什么？（初始状态、最终状态）
- 并发的边界是什么？（同时操作、竞态条件）

**不变原则**：
- 边界情况是 bug 的高发区
- 每个边界至少 1 个测试
- 边界值要具体（不是 "很大的数"，是 "999999"）

**记录**：边界测试清单（边界值 + 预期行为 + 验证点）

### TC4: 错误处理

**问**：
- 可能的错误有哪些？（输入错误、权限错误、系统错误）
- 错误应该怎么处理？（返回错误码、显示提示、重试）
- 错误的优先级是什么？

**不变原则**：
- 错误处理是用户体验的关键
- 每种错误至少 1 个测试
- 错误信息要有用（不是 "Error occurred"）

**记录**：错误测试清单（错误类型 + 触发条件 + 预期响应）

### TC5: 测试数据

**问**：
- 测试数据怎么构造？
- 测试数据要隔离吗？
- 测试数据要清理吗？

**不变原则**：
- 测试数据要可重复（每次跑结果一样）
- 测试数据要隔离（测试之间不互相影响）
- 测试数据要清理（测试后恢复原状）

**记录**：测试数据清单（数据构造 + 隔离策略 + 清理策略）

## 文档约束

**test-cases.md 必须包含：**
1. 测试范围矩阵（验收条件 → 测试用例）
2. 正常路径测试清单（输入 + 预期输出 + 验证点）
3. 边界测试清单（边界值 + 预期行为 + 验证点）
4. 错误测试清单（错误类型 + 触发条件 + 预期响应）
5. 测试数据清单（数据构造 + 隔离策略 + 清理策略）
6. 测试优先级（P0 > P1 > P2）
7. 测试执行顺序（依赖关系 + 并行策略）

**test-cases.md 不应包含：**
- 具体测试代码（那是 生成代码 的事）
- 具体测试框架（那是 technical-design 的事）
- 具体 CI/CD 配置（那是 发布 的事）

## 恒久约定

### 测试范围格式
```markdown
## 测试范围

| 验收条件 | 测试用例 | 优先级 | 状态 |
|---------|---------|--------|------|
| AC-01: 创建任务 | TC-001, TC-002, TC-003 | P0 | 待实现 |
| AC-02: 列表展示 | TC-004, TC-005, TC-006 | P0 | 待实现 |
| AC-03: 任务详情 | TC-007, TC-008, TC-009 | P1 | 待实现 |
```

### 测试用例格式
```markdown
## 测试用例

### TC-001: 创建任务 - 正常路径
**验收条件**：AC-01  
**优先级**：P0  
**输入**：
```json
{
  "title": "完成项目报告",
  "description": "Q3 季度总结",
  "assignee": "user_123"
}
```

**预期输出**：
```json
{
  "id": "task_456",
  "title": "完成项目报告",
  "status": "pending",
  "createdAt": "2026-01-15T10:00:00Z"
}
```

**验证点**：
- 返回 201 Created
- 任务 ID 唯一
- 状态为 pending
- 创建时间为当前时间
```

### 边界测试格式
```markdown
## 边界测试

### TC-002: 创建任务 - 标题为空
**验收条件**：AC-01  
**优先级**：P0  
**边界值**：title = ""  
**预期行为**：返回 400 Bad Request  
**验证点**：
- 错误信息："标题不能为空"
- 不创建任务
- 返回错误字段：["title"]
```

### 错误测试格式
```markdown
## 错误测试

### TC-003: 创建任务 - 未认证
**验收条件**：AC-01  
**优先级**：P0  
**错误类型**：认证错误  
**触发条件**：未提供 Token  
**预期响应**：
- 状态码：401 Unauthorized
- 错误信息："请先登录"
- 重定向到登录页
```

## 入口/出口条件

**入口条件**：
- 有 contract.md + modules/（来自 /forge-detail）
- 有 src/ + tests/（来自 生成代码）
- 或用户已有代码（跳过 build）

**出口条件**：
- 生成了 test-cases.md
- 所有验收条件都有测试用例
- 正常路径、边界情况、错误处理都有覆盖
- 测试数据策略已确定
- 用户确认是否继续（进入 发布）

## 何时不使用

- 只有文档，没有代码（不需要测试用例）
- 已有完整测试用例（直接进入 发布）
- 纯文档项目（跳过测试阶段）

## 红旗清单

- 验收条件没有测试用例 → 强制补充（"每个验收条件至少 1 个测试"）
- 只有正常路径 → 强制补充边界和错误（"边界值是什么？错误怎么处理？"）
- 测试数据不可重复 → 强制隔离（"每次跑结果一样吗？"）
- 测试之间互相影响 → 强制隔离（"测试 A 影响测试 B 吗？"）
- 测试后不清理 → 强制清理（"测试后恢复原状了吗？"）

- [ ] 测试数据是否隔离？
- [ ] 测试数据是否清理？

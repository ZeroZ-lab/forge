# Plan — 任务阶段

## 职责

把详设阶段的 contract.md + modules/ 拆成 AI 可执行的任务序列。每个任务是一个完整的、可独立验证的用户路径。

**原则**：垂直切片不水平分层。每个任务交付一个完整功能路径，不按技术层切片。

## 决策点

### P1: 模块识别

**问**：
- contract.md 里有哪些模块？
- 每个模块包含哪些端点/组件？
- 模块之间的依赖关系是什么？

**记录**：模块清单 + 依赖图

### P2: 垂直切片

**问**：
- 每个模块可以拆成哪些用户路径？
- 每个路径包含哪些层？（schema + API + UI）
- 切片是否完整？（能不能独立验证？）

**记录**：任务清单（每任务：目标 + 文件 + 步骤）

### P3: 拓扑排序

**问**：
- 哪些任务有依赖关系？
- 哪些任务可以并行执行？
- 关键路径是什么？

**记录**：拓扑顺序 + 并行矩阵 + 关键路径

### P4: TDD 结构

**问**：
- 每个任务的验证标准是什么？
- 测试先行还是代码先行？
- 重构的标准是什么？

**记录**：每任务的 TDD 步骤（RED 测试 → GREEN 实现 → REFACTOR 重构）

### P5: 检查点

**问**：
- 哪些任务完成后需要人工审查？
- 检查点的验收标准是什么？
- 检查点不通过怎么办？

**记录**：检查点清单 + 验收标准 + 回退方案

## 文档约束

**plan.md 必须包含：**
1. 模块依赖图（可视化或文本）
2. 任务清单（每任务：目标 + 文件 + 步骤 + 验证标准）
3. 拓扑排序（执行顺序）
4. 并行矩阵（哪些任务可以并行）
5. 关键路径（最短完成时间的路径）
6. 检查点（需要人工审查的节点）
7. TDD 结构（每任务的 RED → GREEN → REFACTOR）

**plan.md 不应包含：**
- 具体代码实现（那是 生成代码 的事）
- 具体测试用例（那是 写测试 的事）
- 具体部署步骤（那是 发布 的事）

## 恒久约定

### 任务格式
```markdown
### Task-01: 创建任务 API
**目标**：实现 POST /tasks 端点  
**依赖**：无  
**文件**：
- src/routes/tasks.ts
- src/schemas/task.ts
- tests/tasks.test.ts

**步骤**：
1. RED：写失败测试（POST /tasks 201）
2. GREEN：实现 schema + route + handler
3. REFACTOR：提取公共逻辑

**验证标准**：
- 测试通过
- 返回 201 + 任务对象
- 错误处理完整（400、401、500）
```

### 依赖图格式
```markdown
## 依赖图

```
Task-01 (创建任务 API)
  ↓
Task-02 (任务列表 API) ← Task-03 (分页中间件)
  ↓
Task-04 (任务详情 API)
  ↓
Task-05 (更新任务 API)
  ↓
Task-06 (删除任务 API)
```
```

### 并行矩阵格式
```markdown
## 并行矩阵

| 任务 | 可并行 | 原因 |
|------|--------|------|
| Task-01 | 否 | 基础模块，其他任务依赖 |
| Task-02 | 是（与 Task-03） | 无共享文件 |
| Task-03 | 是（与 Task-02） | 无共享文件 |
| Task-04 | 否 | 依赖 Task-02 |
```

## 入口/出口条件

**入口条件**：
- 有 contract.md + modules/（来自 /forge-detail）
- 或用户已有详设文档（跳过 detail）

**出口条件**：
- 生成了 plan.md
- 任务清单已定义（每任务：目标 + 文件 + 步骤）
- 拓扑排序已确定（执行顺序）
- 并行矩阵已明确（哪些可以并行）
- 自动推导测试用例（从验收条件 → test-cases.md）
- 用户确认是否继续（进入代码生成）

## 何时不使用

- 只有一个模块（不需要任务分解）
- 已有明确的任务清单（直接进入 生成代码）
- 小功能迭代（简化任务流程）

## 红旗清单

- 任务超过 7 步 → 强制拆分（"能不能拆成两个任务？"）
- 任务涉及超过 5 个文件 → 强制拆分（"能不能缩小范围？"）
- 水平切片（"建所有 DB"） → 强制垂直切片（"一个用户路径是什么？"）
- 没有验证标准 → 强制补充（"怎么知道做对了？"）
- 没有依赖图 → 强制画（"哪些任务有依赖？"）

## 验证清单

- [ ] 任务是否垂直切片（一个完整用户路径）？
- [ ] 每个任务是否 3-7 步、≤5 个文件？
- [ ] 是否有依赖图（可视化或文本）？
- [ ] 是否有拓扑排序（执行顺序）？
- [ ] 是否有并行矩阵（哪些可以并行）？
- [ ] 是否有关键路径（最短完成时间）？
- [ ] 每个任务是否有 TDD 结构（RED → GREEN → REFACTOR）？

## 历史维护（自动）

完成后自动执行，不需要人工触发：

1. **追加 feature changelog.md**（如不存在则创建）：
   ```markdown
   ### v{版本} — {日期} — 任务分解
   - **触发**：{用户说的一句话}
   - **产出**：plan.md（{N} 个任务，关键路径：{路径}）
   - **并行**：{可并行的任务}
   ```

2. **追加 docs/timeline.md**（如不存在则创建）：
   ```markdown
   ### {日期} — {feature} 任务分解
   - 新增：plan.md（{N} 个任务）
   ```

3. **检查膨胀**：timeline.md 或 changelog.md 超过 100 行时，旧记录归档。
